# Phase 1 Implementation

The control plane is split by domain under `control-plane/src`: task state, lease transitions, deadline expiry, private input relay, pool targeting, and public response shaping live in `services/task-service.ts`; machine capability and selected-pool matching in `services/scheduler.ts`; profile ownership, machine pinning, and renewable one-session locks in `services/profile-lock.ts`; and signed webhook construction/delivery in `services/webhook-signer.ts` and `services/webhook-dispatcher.ts`. `storage/repository.ts` is the async persistence boundary; `memory-repository.ts` is the Phase 1 implementation. `http/server.ts` is the Node HTTP adapter and validates all request bodies with zod schemas, caps bodies at 1 MiB, binds worker tokens to machine headers, and exposes both identity-scoped fleet management and authenticated admin registration/rotation endpoints.

The worker package keeps the Oracle-style runtime independent from an executor. `runtime/client.ts` handles claim, heartbeat, result, artifact, and input relay; the executor only sees typed computer-use actions from `protocol/actions.ts`. `runtime/policy.ts` is the masking/handoff policy hook. `executor/browser-executor.ts` adapts Playwright/CDP and contains only browser execution logic.

The public API contract is catalog-ready at `specs/talos-openapi.yaml`. Login-link and hosted-view machinery that depends on Phase 2/3 NyxID connect-link infrastructure returns a documented `not_implemented` error while preserving endpoint and expiry/single-use validation. Webhooks are delivered to callback URLs with bounded retry and HMAC headers. Callback policy is injectable and production should restrict allowed hosts.

Identity trust model: the default `user:<id>` resolver is a development stub only. Production must inject a resolver that verifies the propagated NyxID identity token and derives the authenticated user from NyxID claims. Admin registration requires a separate `TALOS_ADMIN_TOKEN`; worker tokens are rotatable machine credentials. Phase 1 treats `constraints.budget` as advisory metadata and does not enforce spending.

Fleet ownership follows the Oracle user-owned pool model. Authenticated users create private pools with `POST /v1/pools`, enroll machines beneath those pools, rotate their server-issued worker tokens, and manage their own profiles without the platform admin token. Pool and profile listings are identity-filtered and never expose credential hashes or profile lock state. `pool_id` on task submission restricts scheduling to that visible pool, making local versus remote execution a pool-selection decision. The admin surface remains responsible for org/platform pools and deliberate cross-user provisioning.

The worker daemon is `worker/src/daemon.ts`. It validates environment configuration, creates the outbound HTTP client and Playwright/CDP executor, drives a planner-based action loop, renews leases, relays private human input, and handles SIGINT/SIGTERM. The default planner is deterministic and intentionally minimal until the agent-loop spike selects an LLM planner.

Scheduling requires explicit `computer_use: true` machine enrollment for `computer_use` tasks; browser tasks remain capability-neutral and match declared tags and capacity. Requeued leases use a constant priority bucket with original `createdAt` ordering. The public task shape excludes lease, worker, machine, queue, and private input fields; claim responses expose lease credentials only in the dedicated lease fields.
