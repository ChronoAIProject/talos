# Phase 1 Implementation

The control plane is split by domain under `control-plane/src`: task state, lease transitions, deadline expiry, private input relay, pool targeting, and public response shaping live in `services/task-service.ts`; interactive lifecycle, one-action relay, long polling, and mode enforcement live in `services/session-service.ts`; machine capability, pool visibility, and selected-pool matching in `services/scheduler.ts`; profile ownership, machine pinning, and renewable one-session locks in `services/profile-lock.ts`; and signed webhook construction/delivery in `services/webhook-signer.ts` and `services/webhook-dispatcher.ts`. `storage/repository.ts` is the async persistence boundary; `mongo-repository.ts` is the durable implementation and `memory-repository.ts` is the ephemeral local fallback. Pending actions and their correlated results use that same boundary, including atomic enqueue/take operations. `http/server.ts` delegates session routes to `http/session-routes.ts`, caps bodies at 1 MiB generally and 8 MiB only for screenshot-bearing action results, and binds worker tokens to machines.

The worker package keeps the Oracle-style runtime independent from an executor. `runtime/client.ts` handles claim, heartbeat, result, artifact, input relay, and interactive action polling. Autonomous tasks use the planner; interactive tasks bypass it because the NyxID caller is the planner, while the same executor and browser context remain open across calls. `runtime/policy.ts` remains the masking/handoff policy hook. `executor/browser-executor.ts` adapts Playwright/CDP, returns JPEG screenshots by default for normalized interactive actions, and retains explicit PNG support.

The public API contract is catalog-ready at `specs/talos-openapi.yaml`. The control plane loads and validates it once at startup, caches both representations, and serves unauthenticated `/openapi.json` and `/openapi.yaml` metadata routes without filesystem reads per request. Login-link and hosted-view machinery that depends on Phase 2/3 NyxID connect-link infrastructure returns a documented `not_implemented` error while preserving endpoint and expiry/single-use validation. Webhooks are delivered to callback URLs with bounded retry and HMAC headers. Callback policy is injectable and production should restrict allowed hosts.

Identity trust model: `JwtIdentityResolver` is the production path. Configure `TALOS_NYXID_JWT_PUBLIC_KEY` or `TALOS_NYXID_JWKS_URL`, plus `TALOS_NYXID_ISSUER` and `TALOS_NYXID_AUDIENCE`; it verifies NyxID's RS256 assertion and consumes `sub`, `groups`, `roles`, and `permissions` claims (normally a 60-second lifetime). When these are absent, Talos logs loudly and uses the development-only `user:<id>;groups=eng,ops` stub syntax. Admin registration requires a separate `TALOS_ADMIN_TOKEN`; worker tokens are rotatable machine credentials. Phase 1 treats `constraints.budget` as advisory metadata and does not enforce spending.

Fleet ownership follows the Oracle user-owned pool model. Authenticated users create private or org pools with `POST /v1/pools`, enroll machines beneath those pools, rotate their server-issued worker tokens, and manage their own profiles without the platform admin token. Org pools are closed by default and become visible only when the caller's NyxID `groups` intersect `shared_with_groups`; owners can update private/org visibility and sharing with `PATCH /v1/pools/{id}`. Pool and profile listings are identity-filtered and never expose credential hashes or profile lock state. `pool_id` on task submission restricts scheduling to that visible pool, making local versus remote execution a pool-selection decision. Platform pool management remains admin-only.

The worker daemon is `worker/src/daemon.ts`. It validates environment configuration, creates the outbound HTTP client and Playwright/CDP executor, drives autonomous planner tasks or interactive action relay, renews leases, and handles SIGINT/SIGTERM. Interactive polling defaults to two seconds (`TALOS_ACTION_POLL_MS=2000`), backs off transient poll/result failures, and adaptively slows after rate limiting; inactivity fails and closes a session after ten minutes by default (`TALOS_SESSION_IDLE_MS=600000`). The autonomous default planner remains deterministic and intentionally minimal until the agent-loop spike selects an LLM planner.

Deployment uses `control-plane/Dockerfile` for the singleton control plane and `worker/Dockerfile` for Linux platform-pool workers. Kubernetes manifests live under `deploy/k8s/`; the control plane intentionally runs one replica with `Recreate`. MongoDB persistence provides durability, not multi-replica claim atomicity. A future `findOneAndUpdate`-based atomic claim design is required before horizontal scaling.

Scheduling requires explicit `computer_use: true` machine enrollment for `computer_use` tasks; browser tasks remain capability-neutral and match declared tags and capacity. Requeued leases use a constant priority bucket with original `createdAt` ordering. The public task shape excludes lease, worker, machine, queue, and private input fields; claim responses expose lease credentials only in the dedicated lease fields.
